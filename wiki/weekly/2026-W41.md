# Web Accessibility Weekly 2026-W41

## 今週のハイライト

- **ARIA WG が `role=none` からグローバルな state / property を取り除くことを決議した (2026-10-08)。** author が conflict resolution を起こすのを禁じる Issue [w3c/aria#1288](https://github.com/w3c/aria/issues/1288) への対応で、presentational role の扱いに関わる。presentational の継承を廃止する案 ([#2509](https://github.com/w3c/aria/issues/2509)) の結果次第で、関連 PR [#2237](https://github.com/w3c/aria/pull/2237) に影響する ([議事録](https://www.w3.org/2026/10/08-aria-minutes.html))。
- **WCAG 3 で「accessibility supported」の見直し案が出た。** mcking65 の分析 [w3c/wcag3#901](https://github.com/w3c/wcag3/issues/901) と、実装 PR [#902](https://github.com/w3c/wcag3/pull/902) は、この語を「user agent supported method」と「user agent test set」に置き換え、新設の Testing 節に移す。適合主張の中核に関わる提案だが、AGWG の合意を前提とした探索的な案で、決定ではない。
- **AGWG が WCAG の「mechanism」という語の扱いを議論した (2026-10-06)。** 「users can」への言い換え案に、平易さを支持する声と、主語が UA・インターフェースから利用者に移るという法務面などの懸念が出た。決議なし ([議事録](https://www.w3.org/2026/10/06-ag-minutes.html))。
- **WCAG 2 の 4.1.2 の対象を「利用者が設定できる state / property」に限ると Understanding に明記する提案。** `disabled` や `required` は対象外という整理で、自動テストの判定に影響する ([w3c/wcag#5395](https://github.com/w3c/wcag/issues/5395))。起票直後で議論はこれから。
- **ARIA-AT で disabled button のテスト計画が Draft に進んだ (2026-10-07)。** B キーの quick-key が disabled button に移る挙動は、失敗する optional assertion として記録する ([議事録](https://www.w3.org/2026/10/07-aria-at-minutes.html))。
